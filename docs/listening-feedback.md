# CROSS 听后反馈

管理入口：https://cross-today.thebellacross.workers.dev/admin 。仍使用本项目的受保护登录，Mac 上双击 **Open Admin.command**。原来的素材、每日发行、唱片、Selected 和 Bandcamp 导出继续使用。

## 实际操作

1. 在“听后反馈 · 关系实验”选一个档案。不同作品意图可建立不同档案，避免把相反的喜好平均掉。
2. 展开素材列表，明确勾选这次实验的材料，再生成私有试听。云端排队、渲染、失败和完成状态都会保留。
3. 打开试听。时间线显示真实事件与尾音，可听素材、处理后空间前、含空间尾音，也可 Solo / Mute 检查总线前分轨。
4. 选中想改变的事件；勾选要保护的事件、关系或区间。输入听感或选择一个动作。“更多空间”会尝试推迟进入、改变前后角色，文字本身不会成为标签。
5. 听 A/B，明确选择 A、B、都可以、都不喜欢、无法判断或技术问题。理由可留空。Selected、下载及整理备注始终与这些反馈分开。
6. 点击“用已确认反馈训练”。完成后，在模型列表选版本，点击“启用所选版本”。如同时勾选“用于之后的每日发行”，下一批新建发行任务使用这个稳定档案；已排队的作品保留原来的快照。
7. 用“训练如何改变这组提案的排序”查看旧模型与当前模型的分数。分数变化证明软件连接生效，不能单独证明音乐更好。

反馈历史可以更正或撤销。更正/撤销会停用该档案当前模型，防止它继续被新任务使用；原模型和反馈修订仍保留。重新训练，或勾选明确允许恢复历史版本后回退。已经冻结的任务不会被静默改写。

## 系统根据什么改变声音

新引擎先保存 composition plan，再渲染。作品过程、段落、稳定事件 ID、实际素材片段、角色、进入/退出、包络、循环边界、hits 掩码、频谱/颗粒种子、卷积材料、操作参数、声像、宽度、尾音、总线和结束方式都在计划中。新事件和操作使用具名随机流。移动一个事件不会重新抽取其他事件的处理参数。

候选实际改变进入时刻、持续时间、回归、角色、材料、处理或空间关系。每个候选先被渲染，再以处理后时间特征计算关系描述，包括活动密度、留白、回归间隔、前景显著性、局部频带重叠、声像分离、尾音、瞬态和它们的交互。噪声、重叠和密度本身没有“错误”分值。

模型是带 L2 正则化的成对逻辑排序模型，按档案分别训练。它只读取未撤销的明确真人 A/B，使用候选关系特征之差；两者都可、都不喜欢、无法判断和技术问题忠实保存，未强制编码为获胜标签。预测永远不会被当成真人标签继续训练。候选排序与每日生成都会实际读取被启用的模型。保留 20% 探索机会，冷启动全部探索。明确规则与拟合权重分别保存。

模型不确定性采用按父作品家族分组的 16 个 bootstrap 拟合；不足 3 个独立家族时显示无法可靠估计。接近 0.5 的偏好概率不等于模型没把握。模型内部按作品家族留出验证，至少 4 个家族才报告技术预测准确率；这不是艺术评价。

“未训练素材的盲听评估”固定模型版本、拒绝已用于本档案训练的素材、隐藏版本说明，反馈单独保留，不进入训练。需要对未见作品的真实听后判断，才能讨论艺术上的改善。模拟标签只在本地隔离测试存在，未上传到真实档案。

## 声道、控制与锁定

新缓存 `pcm16-native-3` 保留双声道；单声道复制到双声道，超过两声道由 FFmpeg 下混，并记录这个处理。旧 `pcm16-mono-2` 缓存、旧快照和 `engine-v8` 标签保留。原文件只读。每种 transform 的声道路径在 `music/renderer.py` 的 SUPPORT 表中声明。宽度控制 mid/side；声像控制左右平衡，它们不是同一个参数。卷积明确记录所用素材、位置与单声道脉冲下混。

结构探索、变形处理、位运算破坏、总线门控、循环、空间运动/延迟和额外掉音分别控制。原 garble 仅对应额外掉音，不再被说成所有处理的总开关。新生成路径不再让 daily_parameters 随机覆盖这些保存值；旧引擎配置只用于旧发行重放。

事件锁定保护其输入和参数；区间锁定拒绝效果尾音、总线依赖或结束处理范围触及该区间的变体。总线前分轨用于检查，最终 A/B 使用完整总线音频。原始 WAV 与试听 MP3 分开：试听使用每版固定整体 RMS 增益和共同峰值余量，不压缩段内动态；增益另有记录，因此锁定的字节校验针对原始渲染 WAV。RMS 只近似控制整体响度，不保证不同频谱的感知响度完全相等。

跨 CPU、Python、NumPy、FFmpeg 环境不承诺逐字节一致。云端从已有父计划继续比较时，先核验重放 WAV 的完整哈希；不一致就停止，不冒充仅改变一个决定。可以用同批素材建立新的云端父计划。

## 私有存储与重放

反馈、修订、档案和模型索引保存在受保护的 SQLite Durable Object。实验 WAV/MP3、分轨、计划、处理后分析、素材快照、模型及训练记录永久存入现有私有 GitHub Release 存储，标签 `lab-<id>`，每日清理不匹配此命名。公开页面不会得到私人评语、拟合权重、原始路径或凭据。仍是免绑卡方案，未开通 R2，也未改任何付费订阅。

本地迁移：`python scripts/migrate_stereo.py C_SoundSource`。先保留旧快照，再增量添加新声道版本，旧缓存不覆盖。

本地重放：`python scripts/replay_plan.py --plan PLAN.json --snapshot SNAPSHOT.json --cache .cache/audio --output output/replay.wav`。使用计划记录的不可变 engine_ref 与依赖；工具默认拒绝引擎哈希不符。管理页可下载原始 WAV，完整私有计划与报告由受保护媒体入口读取。

基线：提交 `9767d2cfbe5987659aa00593f103093ccaab1e86` / `engine-v8`。配置副本在 `docs/versions/engine-v8-config.json`。旧发行保留其原引擎与实际记录，不把旧摘要补写成当时不存在的完整计划。

方法参考：[成对偏好建模示例](https://botorch.org/docs/tutorials/preference_bo)、[交互式音乐训练界面](https://nime.org/proc/nime2009_fiebrink/index.html)、[频谱描述特征的限制](https://learn.flucoma.org/reference/spectralshape/)。此实现使用 NumPy 实现的正则化排序，不安装 BoTorch，也不调用聊天模型推断听感。
